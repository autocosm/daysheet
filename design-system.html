DaySheet · Design system specimen

Show-day details for touring musicians, as a system

The tokens, components and screens behind the DaySheet prototype, organised as atoms, molecules, organisms and templates. This page is the documentation and the source at once: its stylesheet is the design system, and the token and component data embedded at the end are written for an import into Figma.

Page theme
Reading this pageEvery specimen shows its component name, its Figma variant string and its CSS class. Prefixes mark the atomic layer: a- atom, m- molecule, o- organism. Hover, pressed, focus and disabled are drawn with static classes (is-hover and so on) so each state can be seen side by side and imported. Specimens follow the page theme; templates are shown in a fixed theme.
Overview

Principles

Readiness is derived, never setStatus comes from the data: Needs info, Ready to confirm, Confirmed. There is no hand-set status to drift from the truth.
Shape before colourEvery status has a glyph: a filled check, a ring, a diamond. It still reads in greyscale.
Gradient for brand moments onlyThe primary action, progress and the stage card. Status colours stay flat.
Two elevations and a highlightResting surfaces sit at elevation 1, lifted ones at 2, and every raised surface catches a 1-px top light.
44 px for anything tappableLinks, chips, close buttons and day navigation included.
Dark is a first-class modeEvery semantic colour has a Light and a Dark value. Only the stage, the paper preview and the gels stay fixed.
Foundations

Tokens

Primitives hold raw values. Semantic tokens give them meaning in a Light and a Dark mode. Components read only semantic and dimension tokens, so a theme change never touches a component.

The four facts people need on arrival. A dashed yellow edge marks a gap, and the action says what you can do about it.

Time column on the left, always a start time. Duration and arrival sit under the label.

Date row .m-date-row

Counts only today and dates ahead.

Conventions Naming

  • a- atom, m- molecule, o- organism. Templates are frames marked data-figma-frame.
  • ts- text styles, u- utilities, doc- this page’s chrome (not part of the system).
  • Block, element, modifier: .m-tile, .m-tile__value, .m-tile--gap.
  • Every component root carries data-figma-component, data-figma-variant (“Property=Value, …”) and data-ds-layer.
  • Components read only semantic and dimension tokens, never primitives or literal colours. The exceptions are the always-white text on stage surfaces and the stage lights.
  • .theme-light and .theme-dark force a mode on any frame, whatever the page theme.

Import order Build up, not down

  1. Variables: Primitives, then Semantic (Light and Dark), then Dimension.
  2. Text styles, effect styles, paint styles.
  3. Atoms, then molecules built from atom instances, then organisms built from molecule instances.
  4. Templates as frames, swapping every part for its instance.
  5. Fonts: Avenir Next is on macOS. Where it is missing in Figma, Nunito Sans (Google Fonts) is the intended substitute at the same sizes.
